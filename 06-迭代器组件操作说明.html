06-迭代器组件操作说明 ​

整理日期：2026-05-17
适用范围：neePaaS / 闪用页面 / 迭代器 repeater 组件
目标：把迭代器日常开发中最常用、最容易忘的操作整理成可直接使用的说明。

1. 这篇解决什么问题 ​

迭代器组件常用于把一个数组渲染成多组相同结构的界面，例如：

  • 门机列表
  • 工区时段列表
  • 卡片列表
  • 风险等级列表
  • 嵌套明细列表

日常开发里最常见的问题不是“能不能渲染”，而是：

  • 点击迭代器内部按钮时，如何拿到当前项？
  • 如何拿到当前项的索引？
  • 如何删除当前项？
  • 如何只修改当前项里的某个字段？
  • 如何控制当前项内某个组件显示隐藏？
  • 嵌套迭代器应该怎么组织数据？
  • 点击内部按钮时，如何避免触发外层卡片事件？

核心结论先放这里：

javascript
// 当前点击项的数据
const currentItem = elem.repeater.childData

// 当前点击项在数组中的索引
const currentIndex = elem.repeater.childIndex

只要是在迭代器或列表内部触发插件，优先从 elem.repeater 上取当前项信息。

2. 推荐数据结构 ​

迭代器绑定的数据源建议始终是“对象数组”，并且每一项都有稳定唯一标识。

推荐：

javascript
[
  {
    id: 'crane_001',
    name: '1号门机',
    color: '#2f6df6',
    display: 'none',
    workTimeList: []
  },
  {
    id: 'crane_002',
    name: '2号门机',
    color: '#a333e8',
    display: 'none',
    workTimeList: []
  }
]

不推荐：

javascript
['1号门机', '2号门机', '3号门机']

原因：

  • 字符串数组后续不好扩展字段。
  • 删除、更新、传参时缺少唯一标识。
  • 嵌套迭代器无法自然承载子数组。

字段建议：

  • id：唯一标识，删除和更新优先按它处理。
  • name：展示名称。
  • display：可用于绑定内部组件的 styles.display。
  • children / workTimeList：子级数组，供嵌套迭代器使用。

3. 绑定变量的正确方式 ​

3.1 新建变量 ​

在资源库中新建 Variable，类型建议配置为：

  • 变量类型：数组
  • 数组成员类型：对象
  • 对象成员：按业务字段定义，例如 id、name、display、workTimeList

变量名建议有明确前缀，例如：

text
VAR_craneList
VAR_workTimeList
VAR_riskLevelList

3.2 迭代器绑定变量 ​

在迭代器组件上配置数据绑定：

  • 绑定类型：绑定变量
  • 绑定变量：选择对应变量，例如 VAR_craneList
  • 字段映射：把数组项字段映射到内部组件属性

常见映射例子：

  • name -> 文本组件内容
  • color -> 标题容器背景色
  • display -> 某个组件的 styles.display
  • workTimeList -> 内层迭代器的数据源

3.3 不要在迭代器内部组件重复绑定数据源 ​

常见错误是：外层迭代器已经绑定了变量，又在迭代器内部的文本、按钮、容器组件上单独做数据绑定。

这样容易导致：

  • 每一项显示相同数据。
  • 当前项上下文丢失。
  • 内部组件拿不到正确的 childData。

正确方式是：外层迭代器绑定数组，内部组件通过字段映射显示当前项字段。

4. 获取当前点击项 ​

4.1 基础写法 ​

在迭代器内部按钮、文本、容器等组件绑定点击插件后，可以这样获取当前项：

javascript
function main() {
  const currentItem = elem.repeater.childData
  const currentIndex = elem.repeater.childIndex

  console.log('当前点击项数据:', currentItem)
  console.log('当前点击项索引:', currentIndex)
}

main()

4.2 当前项里的 id ​

javascript
const currentItem = elem.repeater.childData
const currentId = currentItem.id

console.log('当前项ID:', currentId)

如果你的唯一标识字段不是 id，按实际字段改：

javascript
const currentId = currentItem.craneId

4.3 调试建议 ​

第一次写插件时，先打印完整对象：

javascript
console.log('elem:', elem)
console.log('elem.repeater:', elem.repeater)
console.log('当前项:', elem.repeater && elem.repeater.childData)
console.log('当前索引:', elem.repeater && elem.repeater.childIndex)

如果打印结果里没有 elem.repeater，通常说明：

  • 插件不是由迭代器内部组件触发的。
  • 按钮没有真正放在迭代器模板内部。
  • 事件绑定到了外层组件，而不是当前项里的组件。

5. 删除当前项：只做前端过滤 ​

这是最常见场景：迭代器绑定了一个变量数组，点击当前项里的“删除”按钮后，只在前端把这一项过滤掉。

5.1 按 id 删除 ​

适合每项都有稳定 id 的情况。

javascript
function main() {
  const varName = 'VAR_craneList'
  const currentItem = elem.repeater.childData

  if (!currentItem || !currentItem.id) {
    Toast.fail('未获取到当前项ID')
    console.log('当前项:', currentItem)
    return
  }

  const list = getValueByName({
    name: varName,
    type: 'var'
  }) || []

  const nextList = list.filter(item => item.id !== currentItem.id)

  setValueByName({
    name: varName,
    type: 'var',
    value: nextList
  })

  Toast.success('删除成功')
}

main()

5.2 按索引删除 ​

适合临时数据、没有 id 的情况。

javascript
function main() {
  const varName = 'VAR_craneList'
  const currentIndex = elem.repeater.childIndex

  const list = getValueByName({
    name: varName,
    type: 'var'
  }) || []

  if (currentIndex < 0 || currentIndex >= list.length) {
    Toast.fail('未获取到当前项索引')
    console.log('当前索引:', currentIndex)
    return
  }

  const nextList = list.filter((item, index) => index !== currentIndex)

  setValueByName({
    name: varName,
    type: 'var',
    value: nextList
  })

  Toast.success('删除成功')
}

main()

5.3 推荐写法：优先 id，兜底索引 ​

实际项目里建议用这个版本。

javascript
function main() {
  const varName = 'VAR_craneList'
  const currentItem = elem.repeater.childData
  const currentIndex = elem.repeater.childIndex

  const list = getValueByName({
    name: varName,
    type: 'var'
  }) || []

  let nextList = []

  if (currentItem && currentItem.id) {
    nextList = list.filter(item => item.id !== currentItem.id)
  } else if (Number.isInteger(currentIndex)) {
    nextList = list.filter((item, index) => index !== currentIndex)
  } else {
    Toast.fail('未获取到当前项')
    console.log('elem:', elem)
    return
  }

  setValueByName({
    name: varName,
    type: 'var',
    value: nextList
  })

  Toast.success('删除成功')
}

main()

6. 修改当前项字段 ​

点击某一项后，只修改这一项的某个字段。

例子：点击当前项后，把当前项的 selected 改成 true。

javascript
function main() {
  const varName = 'VAR_craneList'
  const currentIndex = elem.repeater.childIndex

  const list = getValueByName({
    name: varName,
    type: 'var'
  }) || []

  const nextList = list.map((item, index) => {
    if (index !== currentIndex) return item

    return {
      ...item,
      selected: true
    }
  })

  setValueByName({
    name: varName,
    type: 'var',
    value: nextList
  })
}

main()

如果要实现“只有当前项选中，其他项取消选中”：

javascript
function main() {
  const varName = 'VAR_craneList'
  const currentIndex = elem.repeater.childIndex

  const list = getValueByName({
    name: varName,
    type: 'var'
  }) || []

  const nextList = list.map((item, index) => ({
    ...item,
    selected: index === currentIndex
  }))

  setValueByName({
    name: varName,
    type: 'var',
    value: nextList
  })
}

main()

7. 控制当前项内部组件显示隐藏 ​

文档里给过一个典型例子：迭代器里点击某个控制组件，只显示当前项的目标组件，其他项隐藏。

7.1 数据结构 ​

变量中准备一个 display 字段：

javascript
[
  { id: '1', name: '1号门机', display: 'none' },
  { id: '2', name: '2号门机', display: 'none' }
]

在迭代器字段映射中，把：

text
display -> 目标组件的 styles.display

7.2 只显示当前项 ​

javascript
function main() {
  const varName = 'VAR_craneList'
  const currentIndex = elem.repeater.childIndex

  const list = getValueByName({
    name: varName,
    type: 'var'
  }) || []

  const nextList = list.map((item, index) => ({
    ...item,
    display: index === currentIndex ? 'block' : 'none'
  }))

  setValueByName({
    name: varName,
    type: 'var',
    value: nextList
  })
}

main()

7.3 点击当前项时切换显示隐藏 ​

javascript
function main() {
  const varName = 'VAR_craneList'
  const currentIndex = elem.repeater.childIndex

  const list = getValueByName({
    name: varName,
    type: 'var'
  }) || []

  const nextList = list.map((item, index) => {
    if (index !== currentIndex) return item

    return {
      ...item,
      display: item.display === 'none' ? 'block' : 'none'
    }
  })

  setValueByName({
    name: varName,
    type: 'var',
    value: nextList
  })
}

main()

8. 新增一项 ​

点击“添加门机”按钮，往迭代器绑定数组里追加一项。

javascript
function main() {
  const varName = 'VAR_craneList'

  const list = getValueByName({
    name: varName,
    type: 'var'
  }) || []

  const nextIndex = list.length + 1

  const newItem = {
    id: `crane_${Date.now()}`,
    name: `${nextIndex}号门机`,
    display: 'none',
    workTimeList: []
  }

  setValueByName({
    name: varName,
    type: 'var',
    value: [...list, newItem]
  })
}

main()

如果业务里需要固定编号，不建议只用 list.length + 1 当唯一标识，因为删除后可能重复。展示名可以用编号，唯一标识建议用后端 ID 或 Date.now() 一类临时 ID。

9. 嵌套迭代器 ​

迭代器支持套嵌。常见结构是外层数组里包含子数组。

9.1 数据结构 ​

javascript
[
  {
    id: 'crane_001',
    name: '1号门机',
    workTimeList: [
      {
        id: 'time_001',
        name: '上午时段',
        startTime: '08:00',
        endTime: '12:00'
      }
    ]
  },
  {
    id: 'crane_002',
    name: '2号门机',
    workTimeList: []
  }
]

9.2 绑定方式 ​

外层迭代器：

text
绑定变量：VAR_craneList

内层迭代器：

text
绑定字段：workTimeList

具体界面配置以平台版本为准，核心原则是：内层数据来自外层当前项的子数组。

9.3 给当前门机新增工区时段 ​

这个按钮通常放在外层迭代器内部、内层迭代器上方。

javascript
function main() {
  const varName = 'VAR_craneList'
  const craneIndex = elem.repeater.childIndex

  const list = getValueByName({
    name: varName,
    type: 'var'
  }) || []

  const nextList = list.map((crane, index) => {
    if (index !== craneIndex) return crane

    const workTimeList = crane.workTimeList || []

    return {
      ...crane,
      workTimeList: [
        ...workTimeList,
        {
          id: `time_${Date.now()}`,
          name: `工区时段${workTimeList.length + 1}`,
          startTime: '',
          endTime: ''
        }
      ]
    }
  })

  setValueByName({
    name: varName,
    type: 'var',
    value: nextList
  })
}

main()

9.4 删除当前门机下的某个工区时段 ​

嵌套迭代器里点击内层删除按钮时，实际能拿到的 elem.repeater.childData 可能是内层当前项。不同平台版本对父级索引暴露方式可能有差异。

稳妥做法：在内层数据中同时保存父级标识。

javascript
{
  id: 'time_001',
  parentCraneId: 'crane_001',
  name: '上午时段'
}

删除时按 parentCraneId + 当前时段 id 过滤：

javascript
function main() {
  const varName = 'VAR_craneList'
  const currentTime = elem.repeater.childData

  if (!currentTime || !currentTime.id || !currentTime.parentCraneId) {
    Toast.fail('未获取到当前时段')
    console.log('当前项:', currentTime)
    return
  }

  const list = getValueByName({
    name: varName,
    type: 'var'
  }) || []

  const nextList = list.map(crane => {
    if (crane.id !== currentTime.parentCraneId) return crane

    return {
      ...crane,
      workTimeList: (crane.workTimeList || []).filter(time => time.id !== currentTime.id)
    }
  })

  setValueByName({
    name: varName,
    type: 'var',
    value: nextList
  })

  Toast.success('删除成功')
}

main()

10. 多个按钮共用一个插件 ​

如果一组按钮都放在迭代器里，也可以共用一个插件，通过 elem.suffix 区分按钮。

示例：

javascript
function removeItem() {
  console.log('执行删除')
}

function editItem() {
  console.log('执行编辑')
}

function addChildItem() {
  console.log('执行新增子项')
}

function main() {
  console.log('elem:', elem)

  switch (elem.suffix) {
    case 'delete':
      removeItem()
      break
    case 'edit':
      editItem()
      break
    case 'addChild':
      addChildItem()
      break
    default:
      console.log('未匹配按钮:', elem.suffix)
  }
}

main()

适合这些场景：

  • 卡片里有“编辑 / 删除 / 查看”多个按钮。
  • 多个按钮逻辑相关，想集中维护。
  • 不想为每个按钮创建一个插件。

11. 阻止事件冒泡 ​

如果迭代器外层卡片也绑定了点击事件，而卡片内部按钮也绑定了点击事件，就可能出现：

  • 点击“删除”按钮，同时触发卡片点击。
  • 点击“编辑”按钮，同时跳转详情页。
  • 内层按钮执行完，外层事件又覆盖状态。

处理方式：

  1. 在按钮组件事件配置里开启阻止冒泡。
  2. 如果平台事件参数里提供原生事件对象，可在插件里尝试：
javascript
if (eventArgs && eventArgs.event && eventArgs.event.stopPropagation) {
  eventArgs.event.stopPropagation()
}

更推荐使用平台组件配置里的“阻止冒泡”能力，因为文档里明确有这个配置方式。

12. 调用后端插件时传当前项 ​

如果不仅要前端过滤，还要调用后端插件处理当前项，可以把当前项或当前项 ID 放进 xplugin_data。

javascript
async function main() {
  const pluginId = 'ingin_demo'
  const currentItem = elem.repeater.childData

  if (!currentItem || !currentItem.id) {
    Toast.fail('未获取到当前项ID')
    return
  }

  const resp = await invokeBackPlugin(pluginId, {
    xplugin_func: 'delete_crane',
    xplugin_data: {
      id: currentItem.id,
      item: currentItem
    }
  })

  console.log('后端插件返回:', resp)
}

main()

如果只是当前页面临时删除，不需要后端持久化，就不要调用后端插件，直接前端过滤即可。

13. 常见坑 ​

13.1 elem.repeater.childData 是空 ​

排查：

  • 插件是否绑定在迭代器内部组件上？
  • 当前组件是否真的在迭代器模板内？
  • 是否点击的是外层容器，而不是每一项内部的按钮？
  • 是否把数据绑定到了内部组件，破坏了迭代器上下文？

13.2 删除后页面没有刷新 ​

排查：

  • 是否调用了 setValueByName 回写变量？
  • name 是否写的是变量名，而不是组件名？
  • type 是否是 'var'？
  • 迭代器绑定的变量是否就是这个变量？

正确回写：

javascript
setValueByName({
  name: 'VAR_craneList',
  type: 'var',
  value: nextList
})

13.3 按索引删除删错项 ​

可能原因：

  • 数组排序发生变化。
  • 页面数据被过滤过。
  • 嵌套迭代器中索引不是你以为的外层索引。

建议：

  • 每项都放 id。
  • 删除优先按 id，不要长期依赖索引。

13.4 嵌套迭代器不知道父级是谁 ​

建议在子项里冗余父级 ID：

javascript
{
  id: 'time_001',
  parentCraneId: 'crane_001'
}

这样删除和更新子项时不依赖父级索引。

13.5 点删除时触发了卡片点击 ​

这是事件冒泡问题。给删除按钮配置阻止冒泡。

16. 推荐实践 ​

迭代器开发时，建议固定遵守这几条：

  1. 迭代器数据一律用对象数组。
  2. 每一项都放稳定唯一 id。
  3. 内部按钮取当前项时优先用 elem.repeater.childData。
  4. 删除优先按 id，不要长期依赖索引。
  5. 修改数组后必须通过 setValueByName 回写变量。
  6. 嵌套迭代器的子项建议冗余父级 ID。
  7. 内部按钮可能触发外层事件时，配置阻止冒泡。
