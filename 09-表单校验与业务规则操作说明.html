09-表单校验与业务规则操作说明 ​

适用对象：闪搭表单编辑、表单保存前校验、表单业务规则、字段初始化、字段值变化、子表字段显隐/只读控制。

这篇只整理在线文档里明确出现过的能力：表单校验插件、业务规则、recordData、eventFieldId、childData、setChildFieldsAttr、MessageBox 等。

1. 先分清三类能力 ​

1.1 表单校验插件 ​

用于“保存之前”判断数据能不能保存。

文档里的核心规则：

  • 表单保存时可以自定义保存校验规则。
  • 校验函数返回 [pass, errMsg]。
  • pass 为 true 表示校验通过。
  • pass 为 false 表示校验不通过。
  • errMsg 是校验失败时提示给用户看的信息。
  • 校验里可以使用异步查询。

1.2 前端插件 ​

用于表单编辑过程中的交互逻辑。

文档里明确提到的表单编辑相关场景包括：

  • 表单初始化。
  • 字段初始化。
  • 字段变化。
  • 按钮点击。
  • 子表新建。

常用变量：

  • recordData：当前表单数据对象。
  • childData：当前插件对应的子表数据对象。
  • childFieldId：发生子表新建的主表子表字段 ID。
  • eventFieldId：发生数值变化的字段 ID。

1.3 业务规则 ​

用于表单保存之后或特定事件发生后，做跨表单数据处理、通知、API 调用、插件调用等。

文档里明确说明：

  • 业务规则可用于处理表单与表单之间的数据关联变更、发送通知、引用执行插件。
  • 一个表单可设置多个业务规则。
  • 多个业务规则会按照插件设置先后顺序依次执行。

2. 表单校验插件返回格式 ​

表单校验插件的返回值是数组：

javascript
return [true, '']

校验失败：

javascript
return [false, '错误提示']

异步校验时，文档示例使用 Promise 包一层：

javascript
let validateFunc = async () => {
  return [true, '']
}

return new Promise(resolve => {
  validateFunc().then(result => {
    resolve(result)
  })
})

实际写校验时，只要最终返回的是 [pass, errMsg] 即可。

3. 保存前基础校验 ​

3.1 文本字段包含敏感词 ​

文档模板里给了文本字段校验示例。

javascript
if (recordData[textFieldId].search('敏感词') >= 0) {
  return [false, '包含敏感词']
}

return [true, '']

整理成更完整的写法：

javascript
const textValue = recordData[textFieldId] || ''

if (textValue.search('敏感词') >= 0) {
  return [false, '包含敏感词']
}

return [true, '']

3.2 数字字段不能超过上限 ​

文档模板示例：

javascript
if (recordData[numFieldId] >= 100) {
  return [false, '金额大于允许上限100！']
}

return [true, '']

整理成通用写法：

javascript
const amount = Number(recordData[numFieldId] || 0)

if (amount >= 100) {
  return [false, '金额大于允许上限100！']
}

return [true, '']

4. 子表数据校验 ​

文档模板给出的场景是：校验子表某个字段的合计值是否大于 100。

javascript
if (childFieldId) {
  const childData = recordData[childFieldId]
  if (childData.length > 0) {
    let sum = 0
    childData.forEach(childDataItem => {
      sum += childDataItem[childLocalFieldId]
    })
    if (sum > 100) {
      return [false, '总金额不能大于100！']
    }
  }
}

return [true, '']

整理成更稳的写法：

javascript
const rows = recordData[childFieldId] || []
let sum = 0

rows.forEach(row => {
  sum += Number(row[childLocalFieldId] || 0)
})

if (sum > 100) {
  return [false, '总金额不能大于100！']
}

return [true, '']

常见用途：

  • 子表明细金额合计不能超过主表金额。
  • 子表数量合计不能超过订单数量。
  • 子表至少需要一条明细。
  • 子表某个字段不能重复。

其中“至少一条明细”的写法：

javascript
const rows = recordData[childFieldId] || []

if (rows.length === 0) {
  return [false, '请至少添加一条明细']
}

return [true, '']

5. 外键数据校验 ​

文档模板给出的场景是：根据当前外键字段值，查询外表数据，再判断外表中的某个字段。

javascript
if (fkFieldId) {
  const fkValue = recordData[fkFieldId]
  if (fkFieldId && fkValue) {
    try {
      const fkDataItem = await getFkDataItem(fkFieldId, fkValue)
      if (fkDataItem && fkDataItem[fkLocalFieldId] < 10) {
        return [false, '外表模具寿命不能小于10！']
      }
    } catch (err) {
      console.log(err)
      return [true, '']
    }
  }
}

return [true, '']

整理成通用写法：

javascript
const fkValue = recordData[fkFieldId]

if (!fkValue) {
  return [true, '']
}

try {
  const fkDataItem = await getFkDataItem(fkFieldId, fkValue)

  if (fkDataItem && fkDataItem[fkLocalFieldId] < 10) {
    return [false, '外表模具寿命不能小于10！']
  }
} catch (err) {
  console.log(err)
  return [true, '']
}

return [true, '']

注意：

  • fkFieldId 是主表里的外键字段 ID。
  • fkValue 通常是外表数据的 id。
  • getFkDataItem(fkFieldId, fkValue) 是异步函数，要 await。

6. 重复数据校验 ​

在线文档里有“项目名称和供应商名称已存在”的保存前校验示例。

原始思路：

  1. 获取当前表单模型。
  2. 从 recordData 里取项目和供应商字段值。
  3. 查询是否已经存在相同项目和供应商的数据。
  4. 存在则返回 [false, '项目名称和供应商名称已存在']。
  5. 不存在则返回 [true, '']。
javascript
let validateFunc = async () => {
  const enterpriseMod = getModel('purchase_info')
  let data1 = recordData[enterpriseMod['project_id']]
  let data2 = recordData[enterpriseMod['supplier_id']]
  let field1 = enterpriseMod['project_id']
  let field2 = enterpriseMod['supplier_id']
  let res = await getTableData(enterpriseMod.modelId, `?${field1}=${data1}&${field2}=${data2}`)

  console.log(res)

  if (res) {
    return [false, '项目名称和供应商名称已存在']
  }

  return [true, '']
}

return new Promise(resolve => {
  validateFunc().then(result => {
    resolve(result)
  })
})

如果需要排除当前正在编辑的数据，可以先打印查询结果，确认返回结构后再过滤当前 recordData.id。

7. 多条校验按顺序执行 ​

保存前校验可以按顺序写。只要遇到不通过，就直接返回失败。

javascript
const textValue = recordData[textFieldId] || ''

if (textValue.search('敏感词') >= 0) {
  return [false, '包含敏感词']
}

const amount = Number(recordData[numFieldId] || 0)

if (amount >= 100) {
  return [false, '金额大于允许上限100！']
}

const rows = recordData[childFieldId] || []

if (rows.length === 0) {
  return [false, '请至少添加一条明细']
}

return [true, '']

这种写法的特点：

  • 第一条失败就停止。
  • 用户一次只看到一个错误。
  • 适合保存前校验。

8. 异步校验模板 ​

需要查重、查外表、查后端数据时，用异步校验。

javascript
async function validateFunc() {
  const model = getModel('purchase_info')
  const projectId = recordData[model['project_id']]
  const supplierId = recordData[model['supplier_id']]

  if (!projectId || !supplierId) {
    return [true, '']
  }

  const query = `?${model['project_id']}=${projectId}&${model['supplier_id']}=${supplierId}`
  const res = await getTableData(model.modelId, query)

  if (res) {
    return [false, '项目名称和供应商名称已存在']
  }

  return [true, '']
}

return new Promise(resolve => {
  validateFunc().then(result => {
    resolve(result)
  })
})

注意：

  • 校验插件最终要 resolve [true, ''] 或 [false, '提示']。
  • 查询结果结构不确定时，先 console.log(res)。
  • 校验失败提示要写得像业务语言，不要只写“错误”。

9. 表单编辑插件常用触发点 ​

在线文档里表单编辑插件常见触发点包括：

  • 表单初始化。
  • 字段初始化。
  • 字段变化。
  • 按钮点击。
  • 子表新建。

9.1 表单初始化赋值 ​

文档模板示例说明：在表单初始化、字段初始化、字段变化场景，可以直接修改 recordData。

javascript
recordData[numberFieldId] = 10
recordData[textFieldId] = 'Hello World'

整理成业务写法：

javascript
function main() {
  recordData[numberFieldId] = 10
  recordData[textFieldId] = 'Hello World'
}

main()

9.2 字段变化时联动赋值 ​

字段变化事件里可通过 eventFieldId 判断哪个字段发生变化。

javascript
function main() {
  if (eventFieldId !== sourceFieldId) {
    return
  }

  recordData[targetFieldId] = recordData[sourceFieldId]
}

main()

说明：

  • eventFieldId 是本次数值变化的字段 ID。
  • recordData[eventFieldId] 是当前变化字段的新值。

10. 子表字段显隐和只读控制 ​

在线文档明确给出了 setChildFieldsAttr。

10.1 控制子表字段显示/隐藏 ​

javascript
setChildFieldsAttr(childField, subChildField, 'show', false)

参数含义：

  • childField：主表中的子表字段 ID。
  • subChildField：子表中的字段 ID。
  • 'show'：控制显示或隐藏。
  • false：隐藏。

字段默认显示。设置为 true 或不单独控制时，效果为显示。

10.2 控制子表字段只读/可编辑 ​

javascript
setChildFieldsAttr(childField, subChildField, 'editable', false)

参数含义：

  • childField：主表中的子表字段 ID。
  • subChildField：子表中的字段 ID。
  • 'editable'：控制可编辑或只读。
  • false：只读，不可编辑。

字段默认可编辑。设置为 true 或不单独控制时，效果为可编辑。

10.3 控制全部子表字段 ​

javascript
setChildFieldsAttr(childField, 'all', 'show', false)

10.4 控制单个子表字段 ​

javascript
setChildFieldsAttr(childField, subChildField, 'show', false)

10.5 控制多个子表字段 ​

javascript
setChildFieldsAttr(childField, [subInput, subNumber, subSelect, subDate], 'show', false)

11. 根据字段值动态控制子表字段 ​

在线文档示例：当“模式”的 value 为 1 时展示字段，否则隐藏。

javascript
if (recordData[eventFieldId] === '1') {
  setChildFieldsAttr(childField, [subInput, subNumber, subSelect, subDate], 'show', true)
} else {
  setChildFieldsAttr(childField, [subInput, subNumber, subSelect, subDate], 'show', false)
}

整理成完整插件：

javascript
function main() {
  if (eventFieldId !== modeFieldId) {
    return
  }

  const showDetailFields = recordData[eventFieldId] === '1'

  setChildFieldsAttr(
    childField,
    [subInput, subNumber, subSelect, subDate],
    'show',
    showDetailFields
  )
}

main()

只读联动同理：

javascript
function main() {
  if (eventFieldId !== modeFieldId) {
    return
  }

  const editable = recordData[eventFieldId] === '1'

  setChildFieldsAttr(
    childField,
    [subInput, subNumber, subSelect, subDate],
    'editable',
    editable
  )
}

main()

12. MessageBox 确认与输入 ​

文档中 MessageBox 支持：

  • MessageBox.alert
  • MessageBox.confirm
  • MessageBox.prompt

12.1 确认操作 ​

javascript
MessageBox.confirm('确定作废吗?', '提示', {
  confirmButtonText: '确定',
  cancelButtonText: '取消',
  type: 'warning'
})

常用于按钮点击场景：

javascript
async function main() {
  const ok = await MessageBox.confirm('确定作废吗?', '提示', {
    confirmButtonText: '确定',
    cancelButtonText: '取消',
    type: 'warning'
  }).then(() => true).catch(() => false)

  if (!ok) {
    return
  }

  recordData[statusFieldId] = '作废'
}

main()

12.2 输入内容 ​

javascript
MessageBox.prompt('请输入原因', '提示', {
  type: 'warning'
})

可用于要求用户补充原因：

javascript
async function main() {
  const result = await MessageBox.prompt('请输入作废原因', '提示', {
    type: 'warning'
  }).catch(() => null)

  if (!result) {
    return
  }

  recordData[reasonFieldId] = result.value
}

main()

13. 业务规则配置说明 ​

业务规则入口：

  1. 进入表单设计界面。
  2. 右上方菜单栏点击“业务规则”。
  3. 弹框确认开启业务规则。

关闭业务规则：

  • 进入业务规则编辑界面。
  • 右上方点击关闭业务规则。
  • 弹窗确认禁用。

注意：

  • 关闭业务规则后，已设置的业务规则都不起作用。
  • 在业务规则编辑页面点击“退出”，只是退出编辑页面，不会导致业务规则失效。

14. 业务规则触发事件 ​

文档列出的触发事件包括：

  • 插入
  • 更新
  • 插入或更新
  • 删除
  • 提交
  • 批准
  • 驳回
  • 撤回
  • 外部触发(记录)
  • 外部触发(表)
  • 审核
  • 反审

选择触发事件时，先判断业务属于哪个阶段：

  • 数据创建后处理：用 插入。
  • 数据修改后处理：用 更新。
  • 新增和修改都要处理：用 插入或更新。
  • 删除后联动处理：用 删除。
  • 审批流相关：用 提交、批准、驳回、撤回。
  • 审核相关：用 审核、反审。

15. 业务规则触发条件 ​

文档说明：

  • 状态触发条件用于设置业务规则启动条件。
  • 触发条件可添加多条。
  • 多条状态触发条件可以设置关系：与 或 或。
  • 事件触发条件用于设置业务规则需要有变化。
  • 多个事件条件之间也支持 与 或 或。

文档注释里提到的条件配置项包括：

  • 本表字段：可选本表单中的字段。
  • 条件类型：相等、不等于、大于、小于、大于等于、小于等于、为空、非空、更新。
  • 取值类型：固定值、选择键值、字段值。
  • 固定值：填写的固定值需要和字段内容类型一致。
  • 选择键值：适用于下拉选择框、单选框。
  • 字段值：同表中的两个字段进行比较。

注意：

  • 大于、小于、大于等于、小于等于仅适用于数字控件。
  • 多个触发条件是否同时满足，取决于条件关系配置。

16. 业务规则动作 ​

文档列出的动作执行时间：

  • 立即
  • 定时

文档列出的动作类型：

  • 表单
  • 通知
  • API调用
  • 插件调用

相关配置项：

  • 周期设置：触发条件或动作执行时间为定时时出现。
  • 外表表单：动作类型选择表单时出现。
  • 通知类型：动作类型选择通知时出现。
  • API：动作类型选择 API 调用时出现。
  • 选择插件：动作类型选择插件调用时出现。
  • 外表操作：外表表单选择表单时，对选择表单执行插入、更新、删除。
  • 赋值设置：满足触发条件之后，对选中表单进行赋值。
  • 外表过滤条件：外表操作选择更新后，用来筛选要更新的记录。
  • 人员、人员组：通知对象。

17. 业务规则赋值设置 ​

文档说明：赋值设置是对选中的外表表单进行赋值操作。

文档注释里提到的赋值配置项包括：

  • 外表字段：外表表单中选定表单的字段。
  • 赋值动作：赋值、加、减、乘、除、平均、最小、最大。
  • 赋值类型：固定值、选择键值、本表字段、指向本表记录。
  • 固定值：需要和字段内容类型一致。
  • 选择键值：适用于下拉选择框、单选框。
  • 本表字段：用本表字段给外表字段赋值。
  • 指定本表记录：当选中表单有外表指向本表时才可选择。

注意：

  • 赋值 适用于多种类型字段。
  • 加 适用于文本字段和数字字段。
  • 其他计算动作只适用于数字字段。

18. 业务规则外表过滤条件 ​

文档说明：外表过滤条件是在表单赋值前做的基础过滤，用来筛选满足条件的外表记录。

文档注释里提到的配置项包括：

  • 外表字段：选中表单中的字段以及外表数据 ID。
  • 条件类型：相等、不等于、大于、小于、大于等于、小于等于、为空、非空。
  • 取值类型：固定值、选择键值、本表字段、指向本表记录。

注意：

  • 大于、小于、大于等于、小于等于仅适用于数字控件。
  • 外表操作选择“更新”时，外表过滤条件很关键，否则可能更新不到目标记录。

19. 业务规则和前端校验怎么选 ​

这部分是基于文档能力的整理，不是新增 API。

推荐区分：

  • 保存前要阻止用户提交：用表单校验插件。
  • 保存后要联动其他表单：用业务规则。
  • 保存后要发通知：用业务规则通知动作。
  • 保存后要调用 API 或插件：用业务规则 API 调用或插件调用。
  • 编辑过程中字段联动赋值：用表单编辑前端插件。
  • 编辑过程中控制子表字段显隐/只读：用 setChildFieldsAttr。

举例：

  • “金额不能超过 100，否则不准保存”：表单校验插件。
  • “采购单保存后，自动更新供应商统计表”：业务规则。
  • “选择模式后，子表字段显示不同列”：字段变化插件 + setChildFieldsAttr。
  • “保存后通知某个角色”：业务规则通知。

21. 常见坑 ​

21.1 校验插件没有返回 [true, ''] ​

表单校验插件最终要返回数组。

通过：

javascript
return [true, '']

失败：

javascript
return [false, '错误提示']

21.2 异步校验没有 resolve ​

文档示例使用：

javascript
return new Promise(resolve => {
  validateFunc().then(result => {
    resolve(result)
  })
})

异步校验要确保最终能返回结果。

21.3 把 MessageBox 当成保存前阻断 ​

MessageBox.alert、MessageBox.confirm 是交互弹窗。

保存前是否通过，要看校验插件返回的 [pass, errMsg]。

21.4 子表字段 ID 和主表子表字段 ID 混淆 ​

setChildFieldsAttr(childField, subChildField, attr, value) 里：

  • childField 是主表中的子表字段 ID。
  • subChildField 是子表中的字段 ID。

21.5 业务规则关闭后不生效 ​

文档明确说明：关闭业务规则后，已设置的业务规则都不起作用。

只点击“退出”编辑页面不会关闭业务规则。

21.6 多条业务规则顺序不清楚 ​

文档说明：一个表单可设置多个业务规则，按插件设置先后顺序依次执行。

如果多个规则都改同一张外表，要注意先后顺序。

22. 排查顺序 ​

校验或业务规则不生效时，按这个顺序查：

  1. 确认插件场景是不是表单校验或表单编辑对应事件。
  2. 打印 recordData，确认字段值是否存在。
  3. 打印 eventFieldId，确认字段变化事件是否由目标字段触发。
  4. 校验插件确认最终返回 [true, ''] 或 [false, '提示']。
  5. 异步校验确认 Promise 最终 resolve(result)。
  6. 子表校验确认 recordData[childFieldId] 是数组。
  7. 外键校验确认 fkFieldId 是主表外键字段 ID。
  8. 业务规则确认已开启。
  9. 业务规则确认触发事件选对。
  10. 业务规则确认状态条件、事件条件、动作类型和外表过滤条件配置正确。
