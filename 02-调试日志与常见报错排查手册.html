02-调试日志与常见报错排查手册 ​

适用对象：闪用前端插件调试、闪搭前端插件调试、中台 Function 调试、WebSocket 调试、页面生命周期排查、事件参数排查、加载状态排查。

本篇基于在线文档中明确出现的 console.log(eventArgs)、crLog、showLoading/clearLoading、中台 node.trace/debug/info/warn/error/fatal、node.error、sysInit/pageEnter/rcvParams、UT 自查清单等内容整理。

1. 前端插件先打印什么 ​

在线文档说明：

  • event 是触发插件的事件名，例如 click、dbclick、mousedown、mouseup、mouseover、mouseout、contextmenu 等。
  • eventArgs 是触发事件传递的参数对象。
  • 不同组件、不同事件下的 eventArgs 结构不一样。
  • 可以通过 console.log(eventArgs) 获取详细结构。

推荐开头先打：

javascript
console.log('event', event)
console.log('eventArgs', eventArgs)
console.log('elem', elem)

表单编辑场景还可以打：

javascript
console.log('recordData', recordData)
console.log('eventFieldId', eventFieldId)

表格行按钮场景：

javascript
console.log('button', eventArgs.button)
console.log('row', eventArgs.row)
console.log('rowIndex', eventArgs.rowIndex)

2. crLog 日志 ​

在线文档说明：

  • crLog.info()
  • crLog.debug()
  • crLog.warn()
  • crLog.error()
  • getLogLevel() 查看当前日志级别。
  • setLogLevel() 可输入数字 1~4 或字符串 debug、info、warn、error 设置当前日志级别。

示例：

javascript
crLog.info('test')
crLog.error('error happens: ', err)

常用模板：

javascript
async function main() {
  crLog.info('插件开始执行')

  try {
    crLog.debug('eventArgs', eventArgs)
    // 业务逻辑
  } catch (err) {
    crLog.error('插件执行异常：', err)
  }
}

main()

3. 中台 Function 调试 ​

在线文档说明：

  • 在 flow 中可单独使用 debug 节点。
  • 在 function 内部可使用：
    • node.trace
    • node.debug
    • node.info
    • node.warn
    • node.error
    • node.fatal
  • 默认要用 error 以上级别的错误才会输出到前端页面上。

示例：

javascript
node.error(msg.req.user)

中台接口里常用：

javascript
node.error(['request query', msg.req.query])
node.error(['payload', msg.payload])

4. WebSocket 调试 ​

在线文档里的 crws 示例在各 handler 里打印连接、断开、消息和错误。

javascript
const crws = global.get('crws')

const api = 'example'
const handlers = {
  openHandler: ws => {
    console.log(`${api} connected.`)
  },
  closeHandler: ws => {
    console.log(`${api} disconnected.`)
  },
  messageHandler: (ws, data) => {
    console.log(`${api} received message: ${data}`)
  },
  errorHandler: (ws, err) => {
    console.error(`${api} error: ${err}.`)
  }
}

crws.registerWsApi(api, handlers)

排查 WebSocket 时先确认：

  • openHandler 是否触发。
  • messageHandler 是否收到数据。
  • errorHandler 是否有错误。
  • API 名称是否和前端连接路径一致。

5. showLoading 和 clearLoading ​

在线文档说明：

  • showLoading(text)：屏幕显示加载转圈。
  • clearLoading()：清除屏幕加载转圈。

示例：

javascript
showLoading('加载中')
clearLoading()

推荐模板：

javascript
async function main() {
  showLoading('加载中...')

  try {
    // 异步逻辑
  } catch (err) {
    console.log(err)
    MessageBox.alert(`操作失败：${err}`, '错误', { type: 'error' })
  }

  clearLoading()
}

main()

如果中间有 return，要先 clearLoading()。

6. 页面生命周期排查 ​

在线文档“闪用开发最佳实践”说明：

6.1 sysInit ​

sysInit 会在页面配置加载完之后、页面组件加载之前触发。

适合：

  • 定义全局共享函数。
  • 定义全局变量。

不适合：

  • 做耗时操作。
  • 做异步重任务。

原因：此时页面还是白屏，耗时操作会影响页面加载速度。

6.2 pageEnter ​

pageEnter 会和页面组件加载同时进行。

通常建议：

  • 页面组件初始化逻辑放这里。
  • 一些异步逻辑放这里。

6.3 rcvParams ​

闪用组件收到父页面传递参数时触发。

在线文档说明，闪用组件初始化时序通常是：

text
sysInit -> pageEnter -> rcvParams

如果初始化依赖父页面传参，建议放在 rcvParams。

7. 弹窗内 Webapp 初始化排查 ​

在线文档说明：闪用组件嵌套在 popup 弹框内时有两种模式。

7.1 弹框重新渲染 ​

建议顺序：

  1. 设置 attrs.attrs.params。
  2. 设置 attrs.attrs.ncConfigId。
  3. 弹出 popup。
  4. 内嵌闪用组件在 rcvParams 初始化。

7.2 弹框不重新渲染 ​

建议：

  • 弹出时设置 attrs.attrs.params。
  • 内嵌组件在 rcvParams 初始化。
  • 关闭时通过 attrs.attrs.params 发送复位命令。
  • 子页面收到复位命令后清空变量或组件状态。

如果有多个闪用组件切换，文档建议更倾向于用不同弹框区分不同闪用组件。

8. 事件参数排查 ​

8.1 高级表格行按钮 ​

javascript
console.log(eventArgs.button)
console.log(eventArgs.row)
console.log(eventArgs.rowIndex)

8.2 行内编辑表格自定义操作 ​

javascript
console.log(eventArgs.row)
console.log(eventArgs.column)

8.3 父子页面通信 ​

子页面发送：

javascript
notifyParent({
  type: 'saveSuccess',
  data: {
    id: recordData.id
  }
})

父页面接收：

javascript
console.log('rcvWebappMsg eventArgs', eventArgs)

8.4 iframe 页面消息 ​

外层页面消息插件：

javascript
console.log('eventData', eventData)

9. 接口调试 ​

9.1 前端接口 ​

javascript
async function main() {
  console.log('请求参数', params)

  try {
    const resp = await requestWithToken({
      url,
      method: 'post',
      data: params
    })

    console.log('接口返回', resp)
  } catch (err) {
    console.log('接口异常', err)
  }
}

main()

9.2 中台接口 ​

javascript
node.error(['headers', msg.req.headers])
node.error(['query', msg.req.query])
node.error(['body', msg.req.body])

如果打开 Auth 验证：

javascript
node.error(msg.req.user)

10. Excel 调试 ​

读取 Excel 时先打印表头和行：

javascript
const rows = XLSX.utils.sheet_to_json(workbook.Sheets[sheetName], {
  defval: ''
})

let cols = Object.keys(rows[0])
console.log('cols', cols)
console.log('rows', rows)

中台侧：

javascript
node.error(['cols', cols])
node.error(['rows', rows])

11. 常见问题排查 ​

11.1 插件没触发 ​

检查：

  • 插件场景是否正确。
  • 目标对象是否正确。
  • 对象事件是否正确。
  • 按钮或组件是否真的触发该事件。

先加：

javascript
console.log('插件已触发')
console.log(event)
console.log(eventArgs)

11.2 eventArgs 结构和预期不同 ​

文档明确说不同组件不同事件的 eventArgs 结构不同。

处理方式：

javascript
console.log(JSON.stringify(eventArgs))

确认结构后再取字段。

11.3 页面初始化拿不到父页面参数 ​

原因通常是时序问题。

文档说明时序：

text
sysInit -> pageEnter -> rcvParams

依赖父页面参数的初始化放 rcvParams。

11.4 弹窗再次打开残留上次状态 ​

如果弹窗不重新渲染，组件会保留上次状态。

处理方式：

  • 打开时重新设置变量或组件值。
  • 关闭时复位。
  • Webapp 子组件通过 attrs.attrs.params 接收复位命令。

11.5 老安卓页面报语法错 ​

在线文档提到：可选链 ?. 在一些老安卓手机上不支持，不建议使用。

替代：

javascript
const value = utils.get(obj, 'attr1.attr2.0.attr3')

11.6 加载一直转 ​

检查所有分支是否调用了：

javascript
clearLoading()

尤其是：

  • catch 分支。
  • return 前。
  • 接口失败后。

12. UT 自查清单参考 ​

在线文档里有工站页面 UT 自查清单，里面列了扫码页面、包材接收页面等检查项。整理成通用自查方向：

  • 输入框是否自动 focus。
  • 重新扫描是否清空输入框。
  • 输入回车是否能触发确定或校验。
  • 空值是否有校验。
  • 无效数据是否有校验。
  • 点击确定按钮是否触发相同校验。
  • 退出按钮是否返回正确页面。
  • 明细信息是否能正确带出。
  • 扫码后是否触发对应业务校验。
  • 校验出错是否有明确提示。
  • 完成按钮是否检查未处理问题。

这部分是文档 UT 内容的归纳，用于开发后自测。

13. 推荐排查顺序 ​

  1. 先确认插件是否触发。
  2. 打印 event、eventArgs、elem。
  3. 表单场景打印 recordData、eventFieldId。
  4. 接口场景打印请求参数。
  5. 接口返回后打印完整响应。
  6. 异常分支打印 err。
  7. 检查是否忘记 await。
  8. 检查 showLoading 后是否所有路径都 clearLoading。
  9. 页面初始化问题检查 sysInit/pageEnter/rcvParams 时序。
  10. 移动端问题检查是否用了老安卓不支持语法。
