10-页面跳转与父子页面通信操作说明 ​

适用对象：闪用页面、多页面闪用组件、Webapp 子页面、弹窗内嵌页面、UniApp WebView 场景。

这篇主要解决日常开发里最常见的页面流转问题：页面跳转、打开新窗口、弹窗显示表单或闪用页面、父页面给子页面传参、子页面通知父页面、兄弟页面传参、事件总线通信、手机端返回处理。

1. 先分清几种“页面” ​

低代码平台里“跳页面”并不只有一种含义，先把对象分清，后面写插件会少踩很多坑。

  • 当前浏览器页面

    • 通过 window.location.href、window.parent.location.href、window.open 控制。
    • 适合跳外部系统、打开独立 URL、跳表单详情路由。

  • 闪用组件内部多页面

    • 通过 jumpToPage(pageName, changeRoute) 控制。
    • 适合一个闪用配置里有多个页面，例如 home、detail、edit。

  • 父页面里的 Webapp 子组件

    • 父页面通过设置子组件的 attrs.attrs.params 传参。
    • 子页面通过 rcvParams 事件接收参数。
    • 子页面通过 notifyParent 通知父页面。
    • 父页面通过 rcvWebappMsg 接收子页面消息。

  • 弹窗里的页面

    • 可以用弹窗组件包 Webapp 组件。
    • 也可以用 showIframePopup 打开一个 iframe 页面。

  • UniApp WebView 内的闪用页面

    • 手机 App 里常见。
    • 退出登录、手势返回，需要通过 UniApp WebView SDK 或 uni.postMessage 配合。

2. 普通 URL 跳转 ​

2.1 当前窗口跳转 ​

当前页面直接跳到某个 URL。

javascript
function main() {
  const url = 'https://example.com'
  window.location.href = url
}

main()

如果当前闪用页面被 iframe 或 WebView 包着，且需要让父窗口跳转，可以使用：

javascript
function main() {
  const url = 'https://example.com'
  window.parent.location.href = url
}

main()

2.2 新窗口打开 ​

javascript
function main() {
  const url = 'https://example.com'
  window.open(url)
}

main()

适用场景：

  • 打开外部系统。
  • 打开报表、打印页、下载页。
  • 不希望离开当前页面。

2.3 跳转后刷新 ​

有些场景修改 URL 后希望立即刷新。

javascript
function main() {
  const url = `${location.origin}/webapp/#/viewer?id=nccfg_demo`
  window.parent.location.href = url
  window.location.reload()
}

main()

注意：

  • window.location.href 改的是当前窗口。
  • window.parent.location.href 改的是父窗口。
  • 如果页面不是被 iframe 包着，window.parent 和 window 可能指向同一个窗口。

3. 闪用内部多页面跳转 ​

如果一个闪用配置里搭了多个页面，使用 jumpToPage。

3.1 基础写法 ​

javascript
function main() {
  jumpToPage('home')
}

main()

home 是页面名称，不是页面标题。建议在页面配置里确认实际页面名。

3.2 带路由变化的跳转 ​

jumpToPage 支持第二个参数 changeRoute，用于控制是否改变路由。不同版本表现可能略有差异，建议首次接入先在测试页验证。

javascript
function main() {
  jumpToPage('detail', true)
}

main()

3.3 跳转前保存参数 ​

如果 A 子页面跳到 B 子页面，并且要带参数，常用 storageApi 暂存。

javascript
async function main() {
  const row = eventArgs.row

  await storageApi.setItem('currentProduct', {
    id: row.id,
    name: row.name
  })

  jumpToPage('productDetail')
}

main()

目标页面读取：

javascript
async function main() {
  const product = await storageApi.getItem('currentProduct')

  if (!product || !product.id) {
    Message.warning('未获取到产品参数')
    return
  }

  setValueByName({
    name: 'VAR_productId',
    type: 'var',
    value: product.id
  })
}

main()

4. 直接通过 URL 打开闪用页面 ​

4.1 打开闪用配置页面 ​

闪用页面常见路由：

text
${host}/webapp/#/viewer?id=${webappCfgId}

示例：

javascript
function main() {
  const host = window.location.origin
  const webappCfgId = 'nccfg_demo'
  const url = `${host}/webapp/#/viewer?id=${webappCfgId}`

  window.open(url)
}

main()

4.2 直接打开某个子页面 ​

子页面路由规则：

text
${host}/webapp/#/pageview/${pageId}?id=${webappCfgId}

示例：

javascript
function main() {
  const host = window.location.origin
  const pageId = 'page_demo'
  const webappCfgId = 'nccfg_demo'
  const url = `${host}/webapp/#/pageview/${pageId}?id=${webappCfgId}`

  window.open(url)
}

main()

适用场景：

  • 外部系统直接打开某个闪用子页面。
  • 从表格行内按钮打开某个详情页。
  • 分享或收藏某个固定子页面入口。

5. 打开表单或表单详情页面 ​

5.1 独立打开表单详情 ​

表单详情路由：

示例：

function main() {

main()

5.2 独立打开表单列表 ​

function main() {

main()

5.3 独立打开表单视图 ​

表单视图路由：

${host}/app/#/rawTableView/${ncCfgId}

示例：

javascript
function main() {
  const host = window.location.origin

  const url = `${host}/app/#/rawTableView/${ncCfgId}`

6. iframe 弹窗显示页面 ​

表格详情行内按钮里，可以使用 showIframePopup 弹出 iframe 页面。

6.1 弹窗显示表单详情 ​

javascript
function main() {
  const host = window.location.origin
  const modelId = 'ncmod_demo'
  const recordId = recordData.id
  const url = `${host}/app/#/detail/detailPage/${modelId}/${recordId}`

  showIframePopup({
    url,
    title: '详情',
    width: `${window.innerWidth}px`,
    height: `${window.innerHeight}px`
  })
}

main()

注意：

  • recordData.id 是当前行数据 id。
  • width、height 建议带单位，例如 800px、80vw、90vh。
  • 如果使用数字，部分版本可能表现不一致，建议统一字符串。

6.2 弹窗显示闪用页面 ​

javascript
function main() {
  const host = window.location.origin
  const webappCfgId = 'nccfg_demo'
  const url = `${host}/webapp/#/viewer?id=${webappCfgId}`

  showIframePopup({
    url,
    title: '业务页面',
    width: '90vw',
    height: '90vh'
  })
}

main()

7. 弹窗组件内嵌 Webapp 的推荐时序 ​

如果不是 iframe，而是在弹窗组件里放一个 Webapp 组件，推荐按下面顺序做。

7.1 首次打开或需要重新渲染 ​

  1. 设置 Webapp 子组件的 attrs.attrs.params。
  2. 设置 Webapp 子组件的 attrs.attrs.ncConfigId。
  3. 打开弹窗。
  4. 子页面在 rcvParams 事件里初始化。

示例：

javascript
function main() {
  const params = {
    action: 'edit',
    id: recordData.id
  }

  setValueByName({
    name: 'crWebappWidget_detail',
    type: 'elem',
    attr: 'attrs.attrs.params',
    value: params
  })

  setValueByName({
    name: 'crWebappWidget_detail',
    type: 'elem',
    attr: 'attrs.attrs.ncConfigId',
    value: 'nccfg_detail_page'
  })

  setValueByName({
    name: 'popup_detail',
    type: 'elem',
    attr: 'attrs.attrs.popupshow',
    value: true
  })
}

main()

7.2 关闭弹窗后不重新渲染 ​

如果关闭“弹框重新渲染”开关，Webapp 子页面可能不会重新加载。此时建议每次打开都重新设置 params，让子页面通过 rcvParams 自己重置状态。

javascript
function openDetail(row) {
  setValueByName({
    name: 'crWebappWidget_detail',
    type: 'elem',
    attr: 'attrs.attrs.params',
    value: {
      action: 'open',
      id: row.id,
      ts: Date.now()
    }
  })

  setValueByName({
    name: 'popup_detail',
    type: 'elem',
    attr: 'attrs.attrs.popupshow',
    value: true
  })
}

关闭时可以通知子页面复位：

javascript
function closeDetail() {
  setValueByName({
    name: 'crWebappWidget_detail',
    type: 'elem',
    attr: 'attrs.attrs.params',
    value: {
      action: 'reset',
      ts: Date.now()
    }
  })

  setValueByName({
    name: 'popup_detail',
    type: 'elem',
    attr: 'attrs.attrs.popupshow',
    value: false
  })
}

8. 父页面给子 Webapp 传参 ​

父页面通过设置子 Webapp 组件的 attrs.attrs.params 传参。

8.1 父页面发送参数 ​

javascript
function main() {
  const params = {
    type: 'edit',
    data: {
      id: recordData.id,
      source: 'tableRowButton'
    }
  }

  setValueByName({
    name: 'crWebappWidget_webapp_add',
    type: 'elem',
    attr: 'attrs.attrs.params',
    value: params
  })
}

main()

8.2 子页面接收参数 ​

在子 Webapp 页面配置触发器：

  • 触发器：系统
  • 事件：rcvParams

插件里读取 eventArgs.params。

javascript
function main() {
  const params = eventArgs.params || {}

  console.log('父页面传入参数：', params)

  if (params.type === 'edit' && params.data?.id) {
    setValueByName({
      name: 'VAR_recordId',
      type: 'var',
      value: params.data.id
    })
  }
}

main()

8.3 为什么推荐在 rcvParams 初始化 ​

闪用组件初始化时序通常是：

text
sysInit -> pageEnter -> rcvParams

如果页面初始化依赖父页面传参，建议把核心初始化放在 rcvParams，因为这个事件能拿到父页面传来的参数。

9. 子 Webapp 通知父页面 ​

子页面使用 notifyParent。

9.1 子页面发送消息 ​

javascript
function main() {
  notifyParent({
    type: 'saveSuccess',
    data: {
      id: getValueByName({ name: 'VAR_recordId', type: 'var' })
    }
  })
}

main()

9.2 父页面接收消息 ​

父页面配置触发器：

  • 触发器：系统
  • 事件：rcvWebappMsg

插件里读取 eventArgs。

javascript
function main() {
  console.log('子页面消息：', eventArgs)

  if (eventArgs.type === 'saveSuccess') {
    setValueByName({
      name: 'popup_detail',
      type: 'elem',
      attr: 'attrs.attrs.popupshow',
      value: false
    })

    refreshTable()
    Message.success('保存成功')
  }
}

main()

注意：

  • notifyParent 的入参可以自定义。
  • 父页面收到的结构以实际 console.log(eventArgs) 为准。
  • 建议消息里固定带 type 字段，方便父页面区分动作。

10. 兄弟页面或子页面之间传参 ​

父子组件之间用 params 和 notifyParent 最清晰。

如果是子页面 A 跳到子页面 B，或者两个没有直接父子消息链路的页面共享状态，推荐使用 storageApi。

10.1 发送页面写入状态 ​

javascript
async function main() {
  await storageApi.setItem('pageTransferData', {
    from: 'orderList',
    orderId: recordData.id,
    ts: Date.now()
  })

  jumpToPage('orderDetail')
}

main()

10.2 接收页面读取状态 ​

javascript
async function main() {
  const data = await storageApi.getItem('pageTransferData')

  if (!data || !data.orderId) {
    Message.warning('没有获取到订单参数')
    return
  }

  setValueByName({
    name: 'VAR_orderId',
    type: 'var',
    value: data.orderId
  })
}

main()

10.3 用完后清理状态 ​

javascript
async function main() {
  await storageApi.setItem('pageTransferData', null)
}

main()

建议：

  • key 名称加业务前缀，例如 order.currentId、device.detailParams。
  • 带上 ts: Date.now()，方便调试是不是旧数据。
  • 敏感数据不要长期放入缓存。

11. 页面内事件总线通信 ​

平台提供 registerEvent、emitEvent、unregisterEvent，适合 Webapp 页面模块之间通信。

11.1 注册事件 ​

通常在 pageEnter 或初始化插件里注册。

javascript
function closeAlarmTab(args) {
  console.log('关闭弹框事件参数：', args)

  setValueByName({
    name: 'tabs_alarm',
    type: 'elem',
    attr: 'attrs.attrs.popupshow',
    value: false
  })

  setValueByName({
    name: 'tabs_alarm',
    type: 'elem',
    attr: 'styles.display',
    value: 'none'
  })
}

function main() {
  registerEvent('closeAlarmTab', closeAlarmTab, true)
}

main()

unique = true 表示该事件只允许唯一回调，能减少重复注册导致的多次执行。

11.2 发布事件 ​

javascript
function main() {
  emitEvent('closeAlarmTab', {
    reason: 'buttonClick',
    ts: Date.now()
  })
}

main()

11.3 注销事件 ​

注销时必须传入同一个函数引用。

javascript
function closeAlarmTab(args) {
  setValueByName({
    name: 'tabs_alarm',
    type: 'elem',
    attr: 'attrs.attrs.popupshow',
    value: false
  })
}

function main() {
  registerEvent('closeAlarmTab', closeAlarmTab)
  unregisterEvent('closeAlarmTab', closeAlarmTab)
}

main()

注意：

  • 不要用匿名函数注册后又试图注销，函数引用对不上。
  • 长生命周期页面里重复进入时，要避免重复注册。
  • 简单父子传参优先用 params / notifyParent，事件总线适合跨模块通知。

12. iframe 页面向外层页面发消息 ​

如果闪用页面被闪搭页面通过 iframe 嵌入，可以使用 window.parent.postMessage。

12.1 iframe 内发送消息 ​

javascript
function main() {
  const host = location.origin

  window.parent.postMessage({
    action: 'refresh',
    params: {
      ts: Date.now()
    }
  }, host)
}

main()

12.2 外层闪搭页面接收消息 ​

外层页面配置插件：

  • 插件场景：表格详情
  • 目标对象：表格详情
  • 对象事件：页面消息

插件里读取 eventData。

javascript
function main() {
  console.log('页面消息：', eventData)

  if (eventData.action === 'refresh') {
    refreshTable()
  }
}

main()

注意：

  • postMessage 第二个参数建议传明确来源，不要随意用 *。
  • 外层接收后要根据 action 分发业务逻辑。
  • 不要在消息里传敏感数据。

13. 弹窗尺寸与滚动 ​

13.1 绝对模式下弹窗跟随页面缩放 ​

如果希望页面缩放时，弹窗里的内容也一起缩放：

  1. 外部组件处设置弹窗组件宽高为 100%。
  2. 外部组件处关闭“弹框插入 Body”。
  3. 如果需要全屏效果，把“对话框距顶”设置为 0。

13.2 PC 弹窗头尾固定，中间滚动 ​

适合弹窗里使用 Tabs，并且希望顶部、底部固定。

配置思路：

  • 给 crTabs 配置固定高度，例如 80vh、90%、calc(100% - 40px)。
  • 内部拆成 header、body、footer。
  • header 和 footer 固定高度。
  • body 使用动态高度，例如 calc(100% - 100px)。

13.3 移动端 popup 滚不动 ​

如果标签组件 mobile popup 模式下页面滚不动，检查“锁定背景滚动”开关。

处理方式：

  • 关闭标签组件的“锁定背景滚动”。

14. 手机 App 里的跳转与退出 ​

手机 App 常见结构：

text
UniApp 原生登录页 -> UniApp WebView 页面 -> WebView 内嵌闪用页面

14.1 登录后进入 WebView 闪用页 ​

UniApp 侧可以使用 uni.reLaunch，好处是关闭当前登录页，手势返回时不会回到登录页。

javascript
uni.reLaunch({
  url: `/pages/tabPages/home/home?goto=home&ts=${Date.now()}`
})

14.2 闪用页退出登录回 UniApp 登录页 ​

闪用插件中先引入 UniApp WebView SDK，再跳转到手机包提供的删除 token 页面。

javascript
async function main() {
  await SystemJS.import('/webapp/static/uni.webview.1.5.2.js')

  Dialog.confirm({
    title: '提示',
    message: '是否退出?'
  }).then(() => {
    Message({
      type: 'success',
      message: '退出成功!'
    })

    uni.navigateTo({
      url: '/pages/login/easyLogin/deleteToken'
    })
  }).catch(() => {
    Message({
      type: 'info',
      message: '已取消退出'
    })
  })
}

main()

15. 手机 App 手势返回处理 ​

安卓 App 里，如果闪用页面存在内部多页面跳转，需要处理系统手势返回。

基本思路：

  1. UniApp 侧重写 onBackPress。
  2. 如果闪用页面不在根页面，把返回事件传给闪用页面。
  3. 闪用页面维护自己的页面栈。
  4. 闪用页面返回到根页面后，通知 UniApp：后续返回交给系统处理。

15.1 闪用侧维护页面栈 ​

javascript
async function sysInit() {
  await SystemJS.import('/webapp/static/uni.webview.1.5.2.js')
  await storageApi.setItem('pageStacks', [])

  window.rcvUniappMsg = async msg => {
    if (msg && msg.msg === 'back') {
      await rcvBackPress()
    }
  }
}

sysInit()

15.2 常规跳转时入栈 ​

javascript
async function jumpPage(pageName) {
  const pageStacks = await storageApi.getItem('pageStacks') || []

  jumpToPage(pageName)
  pageStacks.push(pageName)

  await storageApi.setItem('pageStacks', pageStacks)

  uni.postMessage({
    data: {
      onRoot: false
    }
  })
}

15.3 收到返回事件时出栈 ​

javascript
async function rcvBackPress() {
  const pageStacks = await storageApi.getItem('pageStacks') || []

  pageStacks.pop()
  const lastPage = pageStacks[pageStacks.length - 1]

  if (lastPage) {
    jumpToPage(lastPage)
  }

  await storageApi.setItem('pageStacks', pageStacks)

  if (pageStacks.length === 0) {
    uni.postMessage({
      data: {
        onRoot: true
      }
    })
  }
}

实际项目里，页面栈是否保存当前页、根页是否入栈，要按页面结构统一约定。

16. 消息窗口获取用户输入 ​

简单输入建议优先使用 MessageBox.prompt。

如果需要自定义多个输入项，可以使用 MessageBox.alert 的 HTML 能力。

javascript
function openInputDialog() {
  const htmlString = `
    <div>
      <span>请选择打印机：</span>
      <select id="choosePrintDevice"></select>
    </div>
    <div>
      <span>每个标签打印份数：</span>
      <input type="number" id="copyNum">
    </div>
  `

  MessageBox.alert(htmlString, '提示', {
    dangerouslyUseHTMLString: true
  }).then(() => {
    const copyNum = document.getElementById('copyNum').value
    console.log('打印份数：', copyNum)
  })

  setTimeout(() => {
    const select = document.getElementById('choosePrintDevice')
    if (!select) {
      return
    }

    const option = document.createElement('option')
    option.text = '默认打印机'
    option.value = 'default'
    select.add(option)
  }, 200)
}

openInputDialog()

注意：

  • dangerouslyUseHTMLString 有安全风险，不要渲染不可信 HTML。
  • 弹窗 DOM 可能还没加载完成，所以示例里用了短延迟。
  • 复杂表单交互更建议做成一个弹窗页面或 Webapp 子组件。

19. 常见坑 ​

19.1 父页面设置 params 后，子页面在 pageEnter 里拿不到 ​

初始化时序通常是：

text
sysInit -> pageEnter -> rcvParams

依赖父页面参数的初始化，放到 rcvParams 更稳。

19.2 设置 ncConfigId 和 params 顺序反了 ​

首次弹出或切换 Webapp 配置时，建议先设置 params，再设置 ncConfigId，最后打开弹窗。

19.3 子页面通知父页面后，父页面没有配置 rcvWebappMsg ​

notifyParent 只是发消息，父页面还要配置系统事件 rcvWebappMsg 才能接住。

19.4 兄弟页面用 notifyParent 硬传 ​

兄弟页面没有直接父子关系时，优先用：

  • storageApi 保存状态后跳转。
  • 或 registerEvent / emitEvent 做事件总线。

19.5 弹窗重复打开但内容还是上一次 ​

可能是弹窗或 Webapp 没有重新渲染。

处理方式：

  • 每次打开都重新设置 attrs.attrs.params。
  • 参数里加 ts: Date.now()。
  • 子页面在 rcvParams 里主动重置变量和组件状态。
  • 必要时关闭弹窗时把 attrs.attrs.ncConfigId 置空。

19.6 URL 里直接拼用户输入 ​

跳转 URL 要做好编码。

javascript
const keyword = encodeURIComponent(inputValue)
const url = `${host}/search?keyword=${keyword}`

19.7 iframe postMessage 没有限制来源 ​

不要随手写：

javascript
window.parent.postMessage(data, '*')

推荐传明确来源：

javascript
window.parent.postMessage(data, location.origin)

20. 排查顺序 ​

页面跳转或通信不生效时，按这个顺序查：

  1. 打印触发器参数：console.log(eventArgs)。
  2. 确认当前插件是否真的触发。
  3. 确认组件名是否正确，例如 crWebappWidget_xxx。
  4. 确认写入路径是否正确：attrs.attrs.params、attrs.attrs.ncConfigId。
  5. 确认子页面是否配置了 rcvParams。
  6. 确认父页面是否配置了 rcvWebappMsg。
  7. 确认 notifyParent 入参是否带 type。
  8. 确认 jumpToPage 的页面名是否为真实页面名。
  9. 确认 storageApi.setItem 是否已经 await。
  10. 确认弹窗是否重新渲染，或子页面是否在 rcvParams 里主动重置。
