12-后端插件与前后端调用操作说明 ​

适用对象：前端调用后端插件、Python 后端插件、WebHook/中台 Function、crmodel 查询、requestBackend、后端 REST query 参数、通知发送、错误码排查。

这篇基于在线文档中明确出现过的后端插件、中台模块、请求接口和错误码内容整理。原文里的真实服务地址、数据库账号、密码等环境信息不摘录，只保留用法结构。

1. 先分清三类后端能力 ​

日常开发里常见的“后端”大致有三类：

  • 前端插件调用后端插件

    • 前端使用 invokeBackPlugin(pluginId, params)。
    • 适合从按钮、表单、表格事件触发后台逻辑。

  • Python 后端插件

    • 使用 CrPlugin SDK。
    • 适合写表单数据增删改查、批量处理、物联网点位操作等。

  • WebHook / 中台 Function

    • 使用 Node 风格的 msg、global、flow、context。
    • 适合对外提供 API、定时任务、访问数据库、调用后台 API。

2. 前端调用后端插件 ​

在线文档中，前端函数 invokeBackPlugin 用于调用后端插件并拿到返回结果。

2.1 基础写法 ​

javascript
const pluginId = 'ingin_xxx'

const params = {
  xplugin_func: 'create_missions',
  xplugin_data: {
    object_pk: recordData.id,
    app: 'ncapp_xxx',
    model: 'ncmod_xxx'
  }
}

let resp = await invokeBackPlugin(pluginId, params)
console.log(resp)

参数说明：

  • pluginId：后端插件 ID。
  • xplugin_func：后端插件内部函数名。
  • xplugin_data：传给后端插件的数据。

2.2 常用封装 ​

javascript
async function callBackPlugin(pluginId, funcName, data) {
  const params = {
    xplugin_func: funcName,
    xplugin_data: data
  }

  return await invokeBackPlugin(pluginId, params)
}

使用：

javascript
const resp = await callBackPlugin('ingin_xxx', 'run_task', {
  object_pk: recordData.id
})

3. Python 后端插件结构 ​

在线文档中的 Python 后端插件使用 CrPlugin。

3.1 导入 SDK ​

python
from xplugin.api.xplugin_sdk import CrPlugin

如果需要时间能力：

python
from xplugin.api.xplugin_sdk import CrTimeZone

CrTimeZone 常用方法：

  • CrTimeZone.now()：获取当前时间。
  • CrTimeZone.timedelta(seconds=60)：获取时间间隔，可用于相加或相减。

3.2 插件函数列表 ​

在线文档示例中通过 xplugin_list 暴露插件函数。

python
xplugin_list = [
    {
        "func": "run_test",
        "args": {
            "type": "global"
        }
    }
]

type 常见值：

  • global：不需要表单数据，任何地方可以执行。
  • per-entry：选择表单内某条数据，可通过 object_pk = kwargs.get('object_pk', None) 获取数据 id。
  • per-table：选择表单内多条数据，可通过 object_pks = kwargs.get('objects', []) 获取数据 id 列表。

3.3 返回结构 ​

文档示例中返回：

python
return {
    'msg': msg,
    'code': 0 if ret else -1,
}

建议保持这种结构，前端拿到后更容易判断。

4. CrPlugin 常用方法 ​

CrPlugin 方法列表：

  • getItem：获取单个对象。
  • getList：获取多个对象。
  • update：更新某条对象。
  • create：创建一条数据。
  • updateOrCreate：创建或更新一条数据。
  • getOrCreate：创建或查询一条数据。
  • bulkCreate：批量创建数据。
  • deleteItem：删除某个对象。
  • deleteList：删除多个对象。
  • getAttr：获取某个对象的单个属性值。
  • getAttrs：获取某个对象的多个属性值。
  • setAttr：设置某个对象的单个属性值。
  • setAttrs：设置某个对象的多个属性值。

4.1 查询单条 ​

python
obj = CrPlugin.getItem("app名称", "表单名称", obj_id)

4.2 条件查询多条 ​

python
query = {"总价__gt": 100}
data_list = CrPlugin.getList("app名称", "表单名称", query)

如果 query 传空字典 {}，表示获取该表单所有数据。

4.3 创建数据 ​

python
data = {
    "总价": 100,
    "总数": 100
}

obj = CrPlugin.create("app名称", "表单名称", data)

4.4 更新数据 ​

python
data = {
    "总价": 100,
    "总数": 100
}

obj = CrPlugin.update("app名称", "表单名称", obj_id, data)

4.5 新建或更新 ​

python
obj, created = CrPlugin.updateOrCreate("app名称", "表单名称", data, query)

created：

  • True：新建。
  • False：更新。

4.6 查询或新建 ​

python
obj, created = CrPlugin.getOrCreate("app名称", "表单名称", data, query)

created：

  • True：新建。
  • False：查询。

4.7 批量创建 ​

python
data_list = [
    {"总价": 100, "总数": 100},
    {"总价": 200, "总数": 200}
]

CrPlugin.bulkCreate("app名称", "表单名称", data_list)

4.8 删除单条 ​

python
CrPlugin.deleteItem("app名称", "表单名称", obj_id)

4.9 按条件批量删除 ​

python
query = {"状态": "作废"}

CrPlugin.deleteList("app名称", "表单名称", query)

5. CrPlugin 字段读写 ​

5.1 读取单个属性 ​

python
price = CrPlugin.getAttr(obj, "总价")

5.2 读取多个属性 ​

python
value_dict = CrPlugin.getAttrs(obj, ["总价", "总数"])

5.3 设置单个属性 ​

python
CrPlugin.setAttr(obj, "总价", 100)

在线文档提醒：setAttr 会直接修改数据库，如果修改多个字段，尽量使用 setAttrs 批量修改。

5.4 设置多个属性 ​

python
CrPlugin.setAttrs(obj, {
    "总价": 100,
    "总数": 200
})

6. CrPlugin 查询操作符 ​

在线文档列出的 query 操作符：

  • gt：大于。
  • gte：大于等于。
  • lt：小于。
  • lte：小于等于。
  • in：在指定集合中。
  • startswith：以指定字符开头。
  • istartswith：以指定字符开头，不区分大小写。
  • endswith：以指定字符结尾。
  • iendswith：以指定字符结尾，不区分大小写。
  • range：在给定区间中。
  • year：按年份查找。
  • month：按月份查找。
  • day：按日期查找。
  • isnull：是否为 None。
  • regex：正则匹配。
  • iregex：正则匹配，不区分大小写。
  • exclude：不包含。
  • contains：包含。
  • icontains：包含，不区分大小写。

示例：

python
query = {"总价__gt": 100}
data_list = CrPlugin.getList("app名称", "表单名称", query)

7. 后端插件常见错误 ​

在线文档列出的常见错误：

  • Invalid argument xxx or you should import query or data

    • 未传入 query 字典或 data 字典，或传入内容不是字典。

  • xxx is not found

    • 字段没有找到，需要核实字段名。

  • get model config defeat

    • 获取表单配置失败。

  • get model class defeat

    • 获取表单类失败。

  • model is is not found

    • 表单没有找到，需要核对 app 名称和表单名称。

  • object is not found

    • 数据对象没有找到，需要核对 query 条件或 id。

  • you should import data or data is not list

    • bulkCreate 需要传入列表。

  • find multiple data to be updated

    • updateOrCreate 或 getOrCreate 找到多条数据，需要核对查询条件。

8. WebHook / 中台 Function 基础 ​

在线文档说明：WebHook 用于服务器端自定义功能开发，可以访问文件、数据库、第三方服务，对外定义 API 接口、定时任务等。

8.1 变量作用域 ​

单节点变量：

javascript
context.set('_VarName', 'test')
const value = context.get('_VarName')

流变量：

javascript
flow.set('_VarName', 'test')
const value = flow.get('_VarName')

全局变量：

javascript
global.set('_VarName', 'test')
const value = global.get('_VarName')

8.2 Function 中引入模块 ​

javascript
const request = require('request')

msg.payload = {}

return msg

8.3 Debug 输出 ​

在线文档说明，Function 内可以使用：

  • node.trace
  • node.debug
  • node.info
  • node.warn
  • node.error
  • node.fatal

文档提醒：默认要用 error 以上级别的错误才会输出到前端页面上。

javascript
node.error(['错误信息', msg.payload])

9. 中台获取请求用户 ​

在线文档说明：使用 httpin 节点并打开 Auth 验证后，可以获取请求用户。

javascript
const request = msg.req
node.error(msg.req.user)

前提：

  • httpin 节点打开 Auth 验证。

10. requestBackend ​

requestBackend 用于中台向后台请求 API。

10.1 API ​

javascript
requestBackend(api, method, data, headers = {}, options = {})

参数说明：

  • api：后台 URL。
  • method：请求方法，例如 GET、POST。
  • data：请求体数据。
  • headers：附加请求头。
  • options：请求配置。

10.2 示例 ​

javascript
const crutil = global.get('crutils')

let response = await crutil.requestBackend(
  '/api/url',
  'GET',
  {
    dataRequired0: 'value0',
    dataRequired1: 'value1'
  },
  {},
  {
    timeout: 1024
  }
)

11. crmodel 查询表单数据 ​

在线文档中，中台可以通过 crmodel 操作表单数据。

11.1 引入模块 ​

javascript
const crmodel = global.get('crmodel')

javascript
let rows = await crmodel.findAll('MES_MACHINE', 'M_MachStatus', {

参数说明：

12. crmodel 获取配置和 ID ​

在线文档给出以下方法：

javascript
const crmodel = global.get('crmodel')

const appId = await crmodel.getAppId(app)
const modelId = await crmodel.getModelId(app, model)
const fieldId = await crmodel.getFieldId(app, model, field)

13. 后端 REST query 参数 ​

在线文档说明：后端支持请求方式：

  • GET
  • HEAD
  • PUT
  • POST
  • DELETE
  • PATCH
  • OPTIONS

13.1 连接符 ​

  • ?：分隔 URL 和参数。
  • &：多个参数之间的并且关系。
  • |：多个参数之间的或者关系。

文档说明：& 的优先级大于 |。

13.2 分页 ​

text
?page=1&page_size=20

13.3 排序 ​

单字段降序：

text
?ordering=-createtime

多字段排序：

text
?ordering=-createtime,ncfld_xxxx

说明：

  • 字段前不加符号或加 + 表示正序。
  • 字段前加 - 表示降序。
  • 多字段排序从左到右优先级依次下降。

13.4 搜索 ​

text
?search=xxxxx

搜索字段默认为表单标题字段，也可以在表单列表配置的可搜索字段中配置。

13.5 字段过滤格式 ​

text
?{field}__{operator}={values}

示例：

text
?ncfld_xxxx__icontains=30

13.6 常用操作符 ​

  • =：等于。
  • exact：等于。
  • iexact：等于，不区分大小写。
  • exclude：不等于。
  • isnull：是否为空。
  • not：不等于。
  • gt：大于。
  • gte：大于等于。
  • lt：小于。
  • lte：小于等于。
  • range：指定范围内。
  • notrange：指定范围外。
  • in：等于指定的某些值。
  • notin：不等于指定的某些值。
  • like：匹配字符串。
  • notlike：不匹配字符串。
  • ilike：匹配字符串，不区分大小写。
  • notilike：不匹配字符串，不区分大小写。
  • regex：正则匹配。
  • notregex：正则不匹配。
  • iregex：正则匹配，不区分大小写。
  • notiregex：正则不匹配，不区分大小写。
  • contains：包含。
  • icontains：包含，不区分大小写。
  • startswith：以指定字符开头。
  • endswith：以指定字符结尾。
  • istartswith：以指定字符开头，不区分大小写。
  • iendswith：以指定字符结尾，不区分大小写。

14. Raw SQL 查询 ​

在线文档给出通过 crmodel.sequelize.query() 访问后台数据表的方式。

示例结构：

javascript
let data = await crmodel.sequelize.query(query, {
  type: Sequelize.QueryTypes.SELECT
})

注意：

  • Raw SQL 更容易写出风险语句。
  • 不要拼接不可信用户输入。

  • 使用 Raw SQL 时先限制查询范围和返回数量。

15. 缓存、并发和锁 ​

在线文档中 crutil 工具包提供：

  • asyncPools：限制并发执行异步任务。
  • crPromiseAll：限制并发执行多个 Promise。
  • generateKey：基于对象生成 hash key。
  • getCacheData：基于 Redis 的缓存数据获取。
  • delCacheData：删除缓存。
  • getLock：获取 Redis 互斥锁。
  • releaseLock：释放 Redis 互斥锁。
  • MessageClient：通知类。
  • dayjs：扩展了插件的 dayjs。

15.1 限制并发 ​

javascript
const crutil = global.get('crutil')

function asyncTask(item) {
  return new Promise(resolve => {
    setTimeout(() => {
      resolve(item * 2)
    }, 1000)
  })
}

const results = await crutil.asyncPools(asyncTask, [1, 2, 3, 4, 5], 2)

15.2 获取和释放锁 ​

javascript
const crutil = global.get('crutil')

const locked = await crutil.getLock(lockName)

if (locked) {
  try {
    await getData(lockName, options)
  } finally {
    await crutil.releaseLock(lockName)
  }
}

在线文档也给了基于数据库事务和 Redis 实现锁的示例。日常开发中，有并发更新计数、编号、库存这类场景时，要考虑锁。

16. MessageClient 通知 ​

在线文档说明：MessageClient 是通知类，目前支持：

  • 邮件：email
  • 短信：sms
  • 企业微信：wework

16.1 引入 ​

javascript
const crutil = global.get('crutil')

16.2 邮件通知 ​

javascript
const crutil = global.get('crutil')

try {
  const client = new crutil.MessageClient('email')

  const options = {
    from: '测试 <notification@cloudred.cn>',
    to: 'user@example.com',
    subject: '测试主题',
    text: '测试内容'
  }

  const { code, msg } = await client.sendMessage(options)

  if (code === -1) {
    node.error(msg)
  }
} catch (e) {
  node.error([e, e.stack])
}

16.3 短信通知 ​

javascript
const crutil = global.get('crutil')

try {
  const client = new crutil.MessageClient('sms')

  const options = {
    phoneNumbers: ['手机号1', '手机号2'],
    templateCode: '短信模板Code',
    templateParams: [{ code: '1111' }, { code: '2222' }]
  }

  const { code, msg } = await client.sendMessage(options)

  if (code === -1) {
    node.error(msg)
  }
} catch (e) {
  node.error([e, e.stack])
}

文档提醒：templateParams 数组长度需要和手机号数组长度一致。

16.4 企业微信通知 ​

javascript
const crutil = global.get('crutil')

try {
  const client = new crutil.MessageClient('wework')

  const options = {
    touser: 'UserID1|UserID2|UserID3',
    msgtype: 'text',
    text: {
      content: '测试内容'
    }
  }

  const { code, msg } = await client.sendMessage(options)

  if (code === -1) {
    node.error(msg)
  }
} catch (e) {
  node.error([e, e.stack])
}

19. 日常场景清单 ​

场景 1：前端按钮调用后端插件处理当前记录 ​

javascript
async function main() {
  const pluginId = 'ingin_xxx'

  const resp = await invokeBackPlugin(pluginId, {
    xplugin_func: 'run_task',
    xplugin_data: {
      object_pk: recordData.id
    }
  })

  console.log(resp)
}

main()

场景 2：后端插件读取当前记录并更新字段 ​

python
from xplugin.api.xplugin_sdk import CrPlugin

xplugin_list = [
    {
        "func": "run_task",
        "args": {
            "type": "per-entry"
        }
    }
]

def run_task(*args, **kwargs):
    object_pk = kwargs.get('object_pk', None)

    if not object_pk:
        return {
            'code': -1,
            'msg': 'object missing'
        }

    obj = CrPlugin.getItem("app名称", "表单名称", object_pk)
    CrPlugin.setAttrs(obj, {
        "状态": "已处理"
    })

    return {
        'code': 0,
        'msg': '完成'
    }

20. 常见坑 ​

20.1 前端调用后端插件没有传 xplugin_func ​

后端插件内部函数需要通过 xplugin_func 指定。

javascript
{
  xplugin_func: 'run_task',
  xplugin_data: {}
}

20.2 per-entry 插件拿不到 object_pk ​

确认后端插件 xplugin_list 中 type 是否是 per-entry，并确认前端传了 object_pk。

20.3 updateOrCreate 匹配出多条 ​

文档错误说明里有 find multiple data to be updated。这说明 query 条件不够唯一，需要收紧查询条件。

20.4 bulkCreate 传的不是列表 ​

bulkCreate 需要传列表。

python
CrPlugin.bulkCreate("app名称", "表单名称", data_list)

20.5 中台拿不到请求用户 ​

先检查 httpin 节点是否打开 Auth 验证。

20.6 Raw SQL 拼接用户输入 ​

Raw SQL 不要直接拼接用户输入。优先使用 crmodel.findAll 这类结构化查询。

20.7 requestBackend 参数位置写错 ​

格式是：

javascript
requestBackend(api, method, data, headers, options)

不要把 timeout 当成 headers 传入。

20.8 锁获取后异常没有释放 ​

用 try/finally 释放锁。

javascript
if (locked) {
  try {
    await doWork()
  } finally {
    await crutil.releaseLock(lockName)
  }
}

21. 排查顺序 ​

前后端调用不通时，按这个顺序查：

  1. 前端先打印 resp。
  2. 确认后端插件 ID 正确。
  3. 确认 xplugin_func 是后端 xplugin_list 中存在的函数。
  4. 确认 xplugin_data 里传了后端需要的参数。
  5. per-entry 场景确认 object_pk。
  6. 后端插件使用 logger.info 或 logger.error 打印。
  7. WebHook Function 使用 node.error 打印。
  8. 中台接口确认 msg.payload 最终被赋值并 return msg。
  9. 查询表单失败时确认 app 名称、表单名称、字段名。
  10. 认证失败时对照错误码 001000、001001。
  11. 参数失败时对照 002000 到 002004。
  12. 并发写数据时确认是否需要锁。
