11-用户角色权限与登录信息操作说明 ​

适用对象：组织架构、角色权限、用户管理、当前登录用户信息、数据权限、列表权限、审批权限、登出插件、UniApp 退出登录、业务中台获取请求用户。

这篇基于在线文档中明确出现的用户、角色、权限与登录相关内容整理。原文中个别示例含具体环境地址和密钥类字段，本手册只保留配置结构和操作方法，不摘录具体敏感值。

1. 系统管理包含什么 ​

在线文档中，系统管理主要用于管理：

  • 组织架构。
  • 权限设置。
  • 人员管理。

前台系统设置还包括：

  • 用户管理。
  • 定时任务。
  • 物联网通知设置。
  • 系统服务配置。

日常开发最常碰到的是：

  • 用户是否能进入某个应用。
  • 某个角色能不能访问表单。
  • 某个角色能不能新增、修改、删除、打印。
  • 数据权限是本人、部门还是全部。
  • 当前登录用户是谁。
  • 如何在插件里按当前用户过滤数据。

2. 组织架构 ​

组织架构用于设置企业内部部门和角色。

主要操作按钮：

  • 展开组织。
  • 收起组织。
  • 保存配置。
  • 发布配置。

组织架构分为两类节点：

  • 非角色节点，也就是部门节点。
  • 角色节点。

2.1 部门节点 ​

部门节点支持：

  • 编辑。
  • 添加。
  • 删除。

删除节点时，如果该节点下有其他节点，也会一并删除。这个操作需要谨慎。

2.2 角色节点 ​

角色节点支持：

  • 编辑。
  • 删除。

在线文档提醒：

text
角色节点为最子级，不可再添加子级。

如果把有子节点的非角色节点编辑为角色节点，系统会出现错误提示。

2.3 配置步骤 ​

text
添加部门 -> 添加角色 -> 保存配置 -> 发布配置

注意：

  • 保存配置只是保存当前修改。
  • 发布配置后，前台才会使用新的组织架构。

3. 权限设置 ​

权限用于设置角色对应用、表单、数据的访问能力。

在线文档说明：权限设置针对角色用户，非角色用户不支持设定。

主要操作按钮：

  • 保存配置。
  • 发布配置。

3.1 权限设置步骤 ​

text
选择角色 -> 选择应用 -> 选择对应表单和权限 -> 保存配置 -> 发布配置

3.2 表单权限 ​

在线文档列出的表单权限包括：

  • 访问。
  • 添加。
  • 修改。
  • 删除。
  • 打印。

说明：

  • 没有访问权限，通常看不到或进不了该表单。
  • 没有添加权限，不能新增记录。
  • 没有修改权限，不能编辑记录。
  • 没有删除权限，不能删除记录。
  • 没有打印权限，不能打印。

3.3 数据权限 ​

在线文档列出的数据权限包括：

  • 本人。
  • 部门。
  • 全部。

含义：

  • 本人：只能查看本人对该表单的修改。
  • 部门：可查看角色所属部门对该表单的修改。
  • 全部：可查看所有人对该表单的修改。

4. 列表权限 ​

列表权限影响前台列表可用功能。

在线文档中提到的列表权限功能包括：

  • 新增。
  • 导入。
  • 导出。
  • 删除。
  • 打印二维码。
  • 列表查询条件。
  • 更多操作。

4.1 新增 ​

点击新增后弹出表单，录入信息后提交，即可新增数据。

4.2 导入 ​

导入分为：

  • 新增导入。
  • 更新导入。

新增导入流程：

text
导入 -> 新增导入 -> 下载数据模板 -> 在模板上录入内容 -> 选择文件

更新导入流程：

text
导出 -> 更改导出数据 -> 导入 -> 更新导入 -> 选择文件

在线文档提醒：

  • 流程表单更新导入前，需要在结束节点将要更新的字段勾选可写。
  • 非流程表单需要在操作权限中，将修改数据时要更新的字段勾选可写。
  • 更新导入需要选择数据匹配字段。
  • 更新导入只能更新已有数据，不能在导出数据里新增数据再导入。

4.3 导出 ​

导出列表数据时：

  • 默认导出列表全部数据。
  • 可以根据查询条件筛选后只导出筛选数据。
  • 开启批量操作的表单可勾选数据导出。
  • 导出时可勾选导出字段。

4.4 删除 ​

删除用于删除具体数据，批量删除需要后台对应表单开启批量操作。

4.5 列表查询条件 ​

可以设置表单控件和系统控件作为列表数据查询条件，通过查询筛选符合条件的数据。

5. 用户管理 ​

用户管理用于展示和管理用户。

在线文档中提到的用户管理功能：

  • 查找。
  • 刷新 / 所有。
  • 添加。
  • 导入。
  • 导出。
  • 同步第三方用户信息。
  • 编辑。
  • 修改密码。
  • 冻结。
  • 激活。
  • 删除。

5.1 用户列表权限 ​

在线文档说明：用户列表目前只支持拥有管理员权限的人员编辑，非管理员人员无用户列表功能。

5.2 添加用户 ​

管理员点击添加，输入用户信息后确认，即可添加用户。

5.3 编辑用户 ​

选择用户列表中的用户，点击编辑，修改后保存。

5.4 删除用户 ​

选择用户后点击删除，弹窗确认后删除。

注意：删除操作不可逆。

5.5 修改密码 ​

选择用户后点击密码或改密，确认新密码后完成修改。

5.6 前台同步用户 ​

在线文档说明：后台用户添加完成后，需要在前台同步。

路径：

text
进入应用页面 -> 进入系统设置 -> 用户管理 -> 点击同步

如果后台添加、修改、删除人员后，前台没有变化，先检查是否执行了同步。

适用场景：

用于读取或选择组织机构中的角色。

适用场景：

7.4 读写权限字段 ​

在线文档说明：

  • 读权限人：设置该表中只有读取权限、没有编辑权限的人员。
  • 读权限组：设置该表中只有读取权限、没有编辑权限的部门或角色。
  • 写权限人：设置该表中有读取以及编辑权限的人员。
  • 写权限组：设置该表中有读取以及编辑权限的部门或角色。

8. 前端插件获取当前登录用户 ​

在线文档说明：前端插件中可以使用：

  • userId：当前登录账号的 id。
  • userList：当前系统所有用户列表。

8.1 根据当前用户过滤数据 ​

表单视图后端过滤示例：

javascript
let queryString = `${userFieldId}=${userId}`

return queryString

含义：只返回用户字段等于当前登录用户的数据。

8.2 获取当前用户完整信息 ​

javascript
let userInfo = userList.find(item => {
  return item.id === userId
})

console.log(userInfo)

文档示例中，用户信息对象可能包含：

  • id
  • username
  • nickname
  • email
  • mobile
  • roles
  • roles_string
  • dept
  • dept_string
  • role
  • groups
  • groups_string
  • tenant_id

实际项目以打印出来的对象为准。

8.3 根据昵称过滤数据 ​

javascript
let userInfo = userList.find(item => {
  return item.id === userId
})

let queryString = `${nickname}=${userInfo.nickname}`

return queryString

注意：

  • nickname 在示例中是通过配置参数列表拿到的字段 ID。
  • 不要把中文字段名直接拼进查询条件。

9. 启动插件缓存用户信息 ​

在线文档中的部门创建案例里，启动插件通过接口获取当前用户信息，并写入 storageApi。

示例结构：

javascript
async function main() {
  let config = {}
  config.url = `/app/crdata/getUserInfo?id=${userId}`
  config.method = 'GET'

  let userData

  try {
    userData = (await request(config))?.data?.data
  } catch (e) {
    console.log('startThePlugin Error:', e)
  }

  let cards = userData.cards
  delete userData.cards

  await storageApi.setItem('userData', userData)

  return { cards: [] }
}

return new Promise(resolve => {
  main().then(permitCards => {
    resolve(permitCards)
  })
})

用途：

  • 页面启动时获取用户信息。
  • 后续插件通过 storageApi.getItem('userData') 使用。
  • 与后端接口交互时携带当前用户上下文。

10. 业务中台获取请求用户 ​

在线文档说明：业务中台使用 httpin 节点，并打开 Auth 验证后，可以从请求对象获取用户信息。

示例：

javascript
const request = msg.req
node.error(msg.req.user)

说明：

  • msg.req.user 是当前请求的用户信息。
  • 前提是 httpin 节点打开 Auth 验证。

11.4 前端校验插件调用接口 ​

在线文档示例是在表单校验中调用接口，并把用户信息从 storageApi 带给后端。

javascript
const deptMgmt = getModel('deptMgmt')

let validateFunc = async () => {
  let data = {}

  for (let key in deptMgmt) {
    if (recordData[deptMgmt[key]] !== undefined) {
      data[key] = recordData[deptMgmt[key]]
    }
  }

  if (recordData.id) {
    data.id = recordData.id
  }

  let config = {
    url: '/app/crdata/deptOperate/',
    method: 'POST',
    data: {
      data,
      userInfo: await storageApi.getItem('userData')
    }
  }

  let res = await request(config)

  if (res.data.sysId) {
    recordData[deptMgmt.sysId] = res.data.sysId
  }

  if (res.data.msg) {
    return res.data.msg
  }

  return [false, '接口请求失败']
}

return new Promise(resolve => {
  validateFunc().then(result => {
    resolve(result)
  })
})

注意：

  • 这类写法依赖前面启动插件已经缓存 userData。
  • 校验插件最终仍要返回 [true, ''] 或 [false, '提示']。

async function main() {

      url: '/pages/login/easyLogin/deleteToken'
    })

    Message({
      type: 'info',
      message: '已取消退出'
    })
  })
}

15. OnePower 用户对接 ​

15.2 用户信息接口 ​

  • getUserInfoUrl

  • projectId

15.3 角色映射 ​

文档中 roleMap 用于将外部平台用户类型映射到低代码平台角色。

结构示意：

javascript
roleMap: {
  '$default': 'user',
  1: 'admin',
  2: 'admin',
  3: 'appadmin',

  }

15.4 常见错误排查 ​

在线文档列出的排查方向：

  • 授权码失效：检查 origin、client_id、client_secret、authHeaders。
  • 手机端登录后显示平台主页而非定制手机页：检查 gotoUrl、外部平台传入的 type、前端静态页包。
  • 登录后显示权限不足：检查 defaultGroup 是否填写，以及对应角色是否配置权限。
  • 租户信息查询失败：检查 AD 账号、公共函数中的管理员账号配置、缓存。
  • 登录后跳转地址错误：检查 isUseSubUrl 和 gotoUrl。
  • 找到相同 username 但 xid 不相等：可检查 isUpdateXid 配置。

16. 权限迁移 ​

在线文档给出两类迁移方式：

  • 通过数据库迁移角色权限。
  • 通过接口迁移角色权限。

16.1 权限相关表 ​

在线文档提到的表：

  • users_usergroup：组织/角色表，同时存储部门与角色记录。
  • org_orgpermissionconfig：角色权限配置表，存储角色配置。
  • users_grouppermission：角色权限配置表，存储权限和数据权限。
  • auth_group_permissions：基础权限表。
  • auth_permission：基础权限定义。
  • permission_fieldpermission：字段权限配置。
  • permission_modelconfig：表单权限配置。

16.2 users_usergroup 关键字段 ​

  • gourp_ptr_id：记录 id，主键。
  • org_id：部门完整编码。
  • is_role：部门或角色，0 表示部门，1 表示角色。
  • mgr_id：部门负责人记录 id。

16.3 users_grouppermission 关键字段 ​

  • data_permission：数据权限，值为 all、group、self。
  • permission_id：权限，外键指向 auth_permission。
  • user_group_id：角色，外键指向 users_usergroup。

16.4 数据库迁移注意事项 ​

在线文档提醒：

text

18. 常见坑 ​

18.1 修改组织架构后没有发布配置 ​

组织架构和权限配置都需要保存并发布。

18.2 后台新增用户后前台看不到 ​

在线文档说明：后台用户添加完成后，需要进入前台系统设置的用户管理里点击同步。

18.3 给非角色节点配置权限 ​

权限设置针对角色用户，非角色用户不支持设定。

18.4 更新导入字段没有可写权限 ​

流程表单需要在结束节点勾选可写字段。

非流程表单需要在操作权限中配置修改数据时可写字段。

18.5 前端过滤把中文字段名当字段 ID ​

过滤字符串应使用字段 ID。

javascript
let queryString = `${userFieldId}=${userId}`

18.6 中台拿不到 msg.req.user ​

先检查 httpin 节点是否打开 Auth 验证。

18.7 OnePower 登录后权限不足 ​

按在线文档排查：

  • defaultGroup 是否填写。
  • defaultGroup 对应角色是否配置权限。

19. 排查顺序 ​

权限或用户问题按这个顺序排查：

  1. 当前用户是否存在、是否激活。
  2. 后台新增或修改用户后，前台是否同步。
  3. 用户是否挂到了正确部门或角色。
  4. 角色节点是否为最子级。
  5. 权限配置是否保存并发布。
  6. 表单是否有访问权限。
  7. 新增、修改、删除、打印权限是否勾选。
  8. 数据权限是本人、部门还是全部。
  9. 需要更新导入时，字段是否可写。
  10. 插件里打印 userId 和 userList.find(item => item.id === userId)。
  11. 中台接口确认 httpin 是否开启 Auth。
  12. 登出异常时检查页面退出插件开关和 logoutType。
